AsBuild

Your AI writes the code. AsBuild checks it against the tests you approved, before you merge. Every requirement you agree gets a test that fails before the change and passes after it. A program on GitHub checks it, and you get a plain receipt on the pull request.

Get it on GitHub See real pull requests

Why

Why an AI's "done" is not enough

AI coding agents now write good code, fast. What they cannot do is vouch for their own work: "all tests pass", from the agent that wrote the code, is a claim, not evidence.

Banks solved this long ago with maker-checker. The person who does the work never approves it; a checker verifies it against evidence, and the record stays. AsBuild applies the same control to AI. Your agent is the maker, AsBuild is the checker, and you sign off. Each pull request ends up showing what you approved before the build, that every agreed test failed before the change and passes after it, who built the change and who merged it.

The name comes from construction, where an as-built drawing records what was actually built, not what was planned.

How it works

How it works

  1. You agree what "done" means.

    Your agent writes each requirement as a concrete example with one test for it, and opens a story pull request. Merging it is your approval, and from then on those tests are locked.

  2. Your agent builds the change,

    in your own setup.

  3. AsBuild checks it on GitHub.

    A program runs each locked test before the change and after it, runs the rest of your tests, and checks that no locked test or protected file was touched.

    Technical readers: tests that fail on the main branch and pass on the pull request, plus a regression run, a hash on the locked tests and a protected-files check.

  4. You read the receipt and merge

    when it says PROVEN. The receipt stays on the pull request.

Verdicts

Four verdicts, in plain words

VerdictWhat it means
PROVENEvery test you approved failed before the change and passes now, none of them was changed, and nothing else broke. Ready for you to merge.
NOT PROVENA test you approved still fails, or something that worked before broke. The receipt says what, in one line, and the work goes back to your agent.
WAITING FOR YOUA decision is yours: for example, new tests to approve, a locked test or a protected file was changed, or a test is missing.
UNRESOLVEDThe check could not finish, for example because the tests could not run. Nothing is claimed.

A program writes each receipt from fixed wording. No AI does.

Limits

What AsBuild does not do

  • It does not write your code; your own agent does.
  • It does not decide whether your requirements are the right ones; you do, when you approve the story.
  • It does not make code bug-free, secure or compliant. It shows that each test you approved failed before the change, passes after it and was not changed, and keeps the record. That is not a promise that the feature does everything you meant.
  • It does not block a merge. The decision stays with you.
  • It does not stop an agent that sets out to fake test results. It catches tests that were changed, skipped, weakened or never failed.

Who it is for

Created for people who merge AI-written code

For people who merge code written by an AI agent and answer for it: solo builders and team leads who work in GitHub with Claude Code. Before you merge, you want evidence, not the agent's word. AsBuild gives it as a receipt in plain words, with the technical detail underneath for anyone who wants it.

Requirements

What you need

A GitHub repository, a Python project tested with pytest, and Claude Code, where AsBuild installs as a plugin. On your computer: Git, the GitHub command-line tool and Python. The install steps are in the README.

Setup in your project is one command in Claude Code and one pull request to merge.

Status
